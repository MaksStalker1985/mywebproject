# GameHub — сайт распространения игр и ПО

Веб-сервер на Django 5.2: каталог игр и программ со скачиванием, форум с доступом по учётной записи,
форма связи с производителем. Интерфейс на трёх языках: русском, английском и украинском.

## Страницы

| Страница | Адрес | Доступ |
|---|---|---|
| Главная | `/ru/` | все |
| Игры / ПО | `/ru/catalog/`, `/ru/catalog/games/`, `/ru/catalog/software/` | все |
| Карточка продукта и скачивание | `/ru/catalog/<slug>/`, `/ru/catalog/<slug>/download/` | все |
| Форум | `/ru/forum/` | **только после входа** |
| Связь с производителем | `/ru/contact/` | все |
| Вход / регистрация | `/ru/accounts/login/`, `/ru/accounts/signup/` | — |
| Восстановление пароля по e-mail | `/ru/accounts/password/reset/` | все |
| **Личный кабинет**: библиотека, история покупок, профиль | `/ru/accounts/cabinet/`, `/ru/accounts/cabinet/orders/`, `/ru/accounts/profile/` | после входа |
| Покупка | `/ru/payments/buy/<slug>/` | после входа |
| **Панель управления** | `/ru/manage/` | группы с правом «панель управления» |
| Django admin | `/ru/admin/` | суперпользователь |

Префикс языка (`/ru/`, `/en/`, `/uk/`) переключается кнопками RU / EN / UK в шапке; при первом заходе язык
выбирается по настройкам браузера.

## Запуск (Windows, PowerShell)

```powershell
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python compile_translations.py
.venv\Scripts\python manage.py migrate
.venv\Scripts\python manage.py seed_demo      # демо-каталог, разделы форума, пользователи
.venv\Scripts\python manage.py runserver
```

Откройте http://127.0.0.1:8000/. Демо-пользователи: `admin` / `admin12345` (администратор),
`tester` / `tester12345` (тестер), `player` / `player12345` (игрок). Смените пароли перед публикацией.

Тесты: `.venv\Scripts\python manage.py test`

## Структура

- `config/` — настройки, корневые URL (`i18n_patterns`)
- `core/` — главная, форма связи (`ContactMessage`), команда `seed_demo`
- `catalog/` — модель `Product` (игра/программа, файл, обложка, счётчик скачиваний)
- `forum/` — разделы, темы, сообщения; все представления под `@login_required`
- `accounts/` — регистрация, вход/выход, личный кабинет, группы пользователей (`roles.py`)
- `payments/` — заказы (`Order`), платёжные системы (Stripe, демо), webhook
- `dashboard/` — панель управления контентом для персонала
- `templates/`, `static/css/site.css`, `static/img/bg-space.svg` — оформление: космический фон, стеклянные панели, неоновые акценты (адаптивное, без внешних зависимостей)
- `locale/en`, `locale/uk` — переводы интерфейса (исходный язык — русский)

## Группы пользователей и доступ

Группы настраиваются в **Панели управления → Группы и доступ** (`/ru/manage/groups/`): создание, изменение,
удаление. У каждой группы есть:

- **название, описание, цвет значка, порядок, ключ** (латиница; имя `auth.Group`);
- **права**:
  - *панель управления* — каталог, форум, заказы, пользователи, группы и вход в Django admin;
  - *модерация форума* — удаление чужих сообщений, ответы в закрытых темах, значок «Команда»;
  - *платные продукты бесплатно* — скачивание без покупки;
  - *тестовые сборки* — доступ к неопубликованным продуктам с отметкой «тестовая сборка»;
  - *группа по умолчанию* — сюда попадают новые пользователи (может быть только одна);
- **доступ к каждому разделу форума**: «Нет доступа» (раздел и его темы скрыты, в том числе на главной),
  «Только чтение» (нельзя создавать темы и отвечать) или «Чтение и запись».

Изначально созданы три группы:

| Группа | Права |
|---|---|
| **Администраторы** (`admins`) | все права; группу нельзя удалить или лишить доступа к панели |
| **Тестеры** (`testers`) | платные продукты бесплатно, тестовые сборки |
| **Игроки** (`players`) | группа по умолчанию, без особых прав |

Пользователь состоит в одной группе; сменить её — **Панель управления → Пользователи** (себя и
суперпользователя изменить нельзя). При удалении группы её участники переходят в группу по умолчанию; группу
по умолчанию удалить нельзя — сначала назначьте другую. Флаг «Статус персонала» (`is_staff`) выставляется
автоматически по праву «панель управления»; суперпользователь имеет все права и видит весь форум.

Хранение: `accounts.Role` (права группы, связь 1:1 с `auth.Group`), `forum.CategoryAccess` (уровень доступа
группы к разделу; нет записи — полный доступ). Проверки — `accounts/roles.py` и `forum/access.py`.

**Тестовая сборка** — продукт с флагами «опубликовано» = нет и «тестовая сборка» = да. В публичном каталоге
его нет; группы с правом «тестовые сборки» (и администраторы) видят его в личном кабинете и могут скачать.

## Личный кабинет (`/ru/accounts/cabinet/`)

- **Моя библиотека** — купленные игры и программы с кнопкой «Скачать», датой покупки, версией и размером.
  Купленный продукт остаётся доступен, даже если его сняли с публикации. Тестерам и администраторам
  здесь же показаны продукты, доступные их группе.
- **История покупок** — все заказы с суммой, статусом, способом оплаты и датами, фильтр по статусу.
  Неоплаченный заказ можно проверить, отменённый — купить снова.
- **Профиль** — данные учётной записи, группа, смена пароля, темы на форуме.
- **Аватар** (в профиле) — JPG, PNG, WebP или GIF до 3 МБ. Картинка обрезается до квадрата 256×256 и
  пересохраняется в WebP: метаданные (EXIF, геолокация) удаляются, файл с «не картинкой» не примется.
  Аватар показывается на форуме, в шапке, в кабинете и в списке пользователей панели. Без загруженного
  аватара показывается первая буква логина на цветном фоне. Администратор может удалить неподходящий
  аватар в **Панели управления → Пользователи**.

Сверху — итоги: сколько продуктов куплено, сколько потрачено, сколько заказов ждут оплаты.

## Восстановление пароля

На странице входа есть ссылка **«Забыли пароль?»**. Пользователь указывает e-mail из регистрации и получает
письмо (текст + HTML) со ссылкой на страницу нового пароля.

- Ссылка одноразовая и действует 2 часа (`PASSWORD_RESET_TIMEOUT` в настройках).
- Ответ одинаковый, есть такой адрес на сайте или нет, — по нему нельзя проверить, зарегистрирован ли e-mail.
- Ограничение частоты: не больше 5 запросов в час с одного IP и 3 писем в час на один адрес
  (`accounts/password_reset.py`). Счётчики хранятся в кеше Django; если сайт работает в нескольких
  процессах, подключите общий кеш (Redis/Memcached), иначе лимит считается в каждом процессе отдельно.
- После смены пароля приходит письмо-уведомление, а входы на других устройствах завершаются.
- Новый пароль проверяется теми же правилами сложности, что и при регистрации.

При разработке письма печатаются в консоль сервера (`core.mail.EmailBackend` — консольный вывод в UTF-8,
стандартный бэкенд Django падает на кириллице в консоли Windows). Ссылку из письма можно скопировать оттуда.

Настоящая отправка — SMTP через переменные окружения:

```powershell
$env:DJANGO_EMAIL_BACKEND = "django.core.mail.backends.smtp.EmailBackend"
$env:EMAIL_HOST = "smtp.example.com"
$env:EMAIL_PORT = "587"
$env:EMAIL_HOST_USER = "noreply@example.com"
$env:EMAIL_HOST_PASSWORD = "..."
$env:EMAIL_USE_TLS = "1"
$env:DEFAULT_FROM_EMAIL = "GameHub <noreply@example.com>"
```

Ссылка в письме строится по адресу, с которого пришёл запрос, поэтому в продакшене задайте
`DJANGO_ALLOWED_HOSTS` только своим доменом.

## Панель управления (`/ru/manage/`)

Доступна группе «Администраторы» (демо-пользователь `admin`).
Ссылка «Панель управления» появляется в шапке.

- **Обзор** — количество игр/программ, скачиваний, продаж, выручка, новые обращения и заказы.
- **Игры и ПО** — добавление, редактирование и удаление продуктов: тип, описание, версия, платформа,
  цена, загрузка обложки и установочного файла, публикация и вывод на главную. Продукт с заказами
  удалить нельзя — его снимают с публикации.
- **Разделы форума** и **Темы форума** — создание разделов, закрепление/закрытие/удаление тем.
- **Обращения** — сообщения из формы связи, отметка «обработано».
- **Заказы** — все покупки с фильтром по статусу.
- **Пользователи** — поиск, фильтр по группе, перевод пользователя в другую группу.
- **Группы и доступ** — права групп и доступ к разделам форума (см. выше).
- В форме продукта есть флаг **«Тестовая сборка»**.

## Платное распространение

У продукта есть поле «Цена»: `0` — бесплатный (скачивают все), больше нуля — платный. Платный продукт
скачивается только после покупки. Цена фиксируется в заказе в момент покупки.

Платёжная система выбирается переменной `PAYMENTS_PROVIDER`:

- `demo` (по умолчанию при `DEBUG=1`) — имитация оплаты без денег, для разработки. При `DEBUG=0`
  отключена.
- `stripe` — безналичная оплата картой (Visa/Mastercard, Apple Pay, Google Pay) через
  [Stripe Checkout](https://stripe.com/docs/payments/checkout). Данные карты вводятся на странице Stripe,
  на наш сервер они не попадают.

Подключение Stripe:

1. Получите ключи в Stripe Dashboard → Developers → API keys (для проверки — тестовые `sk_test_…`).
2. Создайте webhook на `https://<ваш-домен>/payments/webhook/stripe/` с событиями
   `checkout.session.completed`, `checkout.session.async_payment_succeeded`,
   `checkout.session.async_payment_failed`, `checkout.session.expired`.
3. Задайте переменные окружения:

```powershell
$env:PAYMENTS_PROVIDER = "stripe"
$env:PAYMENTS_CURRENCY = "UAH"          # или USD, EUR…
$env:STRIPE_SECRET_KEY = "sk_test_..."
$env:STRIPE_WEBHOOK_SECRET = "whsec_..."
```

Локально webhook можно пробросить через Stripe CLI: `stripe listen --forward-to localhost:8000/payments/webhook/stripe/`.
Статус оплаты также сверяется при возврате покупателя на сайт, поэтому заказ подтвердится даже без webhook.

### Paddle

`PAYMENTS_PROVIDER=paddle` — оплата через [Paddle Billing](https://developer.paddle.com/): карты, PayPal,
Apple Pay, Google Pay. Paddle — Merchant of Record: он официально продаёт товар покупателю и сам
начисляет и платит налоги (VAT, sales tax) во всех странах. Это удобно для продаж игр и ПО по всему миру
и доступно продавцам из стран, где Stripe не работает.

Как это работает: сервер создаёт транзакцию через Paddle API с ценой из заказа, затем страница
`/ru/payments/orders/<id>/paddle/` открывает окно оплаты Paddle.js. Подтверждение приходит webhook-ом
(подпись `Paddle-Signature` проверяется) и дополнительно сверяется, когда покупатель возвращается на сайт.

Подключение:

1. Зарегистрируйтесь в [sandbox-аккаунте Paddle](https://sandbox-vendors.paddle.com/) для проверки
   (потом то же самое в боевом аккаунте).
2. **Developer tools → Authentication**: создайте API key и client-side token.
3. **Checkout → Checkout settings → Default payment link**: `https://<ваш-домен>/payments/paddle/pay/`.
   Без этого Paddle не создаёт транзакции. Для боевого аккаунта домен должен пройти проверку Paddle.
4. **Developer tools → Notifications**: новое назначение `https://<ваш-домен>/payments/webhook/paddle/`
   с событиями `transaction.completed`, `transaction.paid`, `transaction.canceled`,
   `transaction.payment_failed`. Скопируйте секретный ключ.
5. Переменные окружения:

```powershell
$env:PAYMENTS_PROVIDER = "paddle"
$env:PAYMENTS_CURRENCY = "USD"            # валюта должна поддерживаться Paddle
$env:PADDLE_API_KEY = "pdl_sdbx_apikey_..."
$env:PADDLE_CLIENT_TOKEN = "test_..."
$env:PADDLE_WEBHOOK_SECRET = "pdl_ntfset_..."
$env:PADDLE_SANDBOX = "1"                 # 0 — боевой режим (по умолчанию при DEBUG=0)
```

Для локальной проверки webhook нужен публичный адрес, например через `ngrok http 8000`.

### Другие системы

LiqPay, WayForPay, Fondy и т.п. подключаются отдельным классом в `payments/providers.py` с методами
`start_checkout` и `sync`.

## Переводы

Строки в коде помечены `gettext` / `{% translate %}`. Если установлен GNU gettext:

```powershell
.venv\Scripts\python manage.py makemessages -l en -l uk
.venv\Scripts\python manage.py compilemessages
```

Без gettext (обычно на Windows) правьте `locale/*/LC_MESSAGES/django.po` вручную и компилируйте
`python compile_translations.py`.

Сейчас переводится интерфейс; названия и описания продуктов хранятся на одном языке. Для перевода
контента можно подключить `django-modeltranslation`.

## Перед продакшеном

Задайте переменные окружения `DJANGO_SECRET_KEY`, `DJANGO_DEBUG=0`, `DJANGO_ALLOWED_HOSTS`,
`CONTACT_EMAIL` и SMTP-бэкенд (`DJANGO_EMAIL_BACKEND` + настройки `EMAIL_*`). Выполните
`manage.py collectstatic` и отдавайте `static/` и `media/` через веб-сервер (nginx и т.п.); в `media/avatars/` лежат загруженные пользователями аватары. Вместо SQLite
лучше взять PostgreSQL.
